# ProteinToolkit

An integrated protein analysis pipeline: sequence statistics, motif and
catalytic-residue detection, rule-based + machine-learning EC classification,
structural pocket/active-site analysis, and ligand docking (AutoDock Vina),
fused into one confidence-scored report.

## Why

Most tools in this space specialize: a sequence stats calculator, a motif
scanner, a pocket detector, a docking engine. ProteinToolkit runs the
sequence-level triage (stats, motifs, catalytic residues, EC classification)
with **no structure required**, then optionally confirms candidates
structurally (pockets, spatial catalytic-site geometry, docking) — so you can
screen many sequences cheaply and only run the expensive structural stage on
the ones that pass triage.

The closest published prior art is CAPIM (Özsari et al. 2025, *Protein
Science* 34(11):e70347, [doi.org/10.1002/pro.70347](https://doi.org/10.1002/pro.70347)),
which combines pocket detection (P2Rank) + catalytic/EC annotation (GASS) +
docking (AutoDock Vina) into one report. CAPIM's structural methods are more
rigorous than this toolkit's; this toolkit's addition is the sequence-only
triage front end and the hedged-confidence reporting discipline (see
Limitations below).

## Install

```bash
pip install -r requirements.txt
```

Optional, for real docking (not required — falls back to a mock adapter
otherwise): download a precompiled AutoDock Vina binary from
[github.com/ccsb-scripps/AutoDock-Vina/releases](https://github.com/ccsb-scripps/AutoDock-Vina/releases)
and place it at `bin/vina.exe` (see [bin/README.md](bin/README.md)).

## Usage

**Sequence-only analysis** (stats, motifs, catalytic residues, EC classification):

```bash
echo "YOUR_SEQUENCE" | python main.py
```

**With structure** (adds pocket detection, spatial catalytic-site check,
structural active-site prediction) — accepts a local PDB file or a PDB ID,
which is fetched from RCSB automatically:

```bash
echo "YOUR_SEQUENCE" | python main.py 1LYZ
```

**Full pipeline with docking** (receptor + ligand + real Vina docking +
evidence fusion):

```bash
python pipeline.py --pdb 1LYZ --smiles "CC(=O)Oc1ccccc1C(=O)O" --engine vina
```

**Virtual screening** (which of *many* candidate ligands best fits this
receptor? — docks a whole library and ranks by score; receptor prep/pocket
detection run once, not once per candidate):

```bash
python screen.py --pdb 1LYZ --library candidates.smi --engine vina --top 10
```

`candidates.smi` is a text file, one candidate per line: `SMILES [name]`.

> **Read before relying on the ranking.** Benchmarked on two targets
> (50 measured actives vs 50 size-matched measured weak binders each), the
> best-pose Vina score does not separate them from chance: ROC AUC 0.49
> (95% CI 0.38-0.61) on carbonic anhydrase II and 0.60 (0.49-0.70) on
> estrogen receptor α, top-10% enrichment 0.7x and 1.6x (random = 1.0).
> Both intervals include 0.5. This is with a protonated, charged receptor
> (pH 7.4); the unprotonated receptor used earlier gave 0.58 and 0.58, so
> missing receptor hydrogens were not what limited it. Vina is useful for
> generating plausible poses in a known site; it is not a validated way to
> rank compounds by potency. See [Validation](#validation).

**Batch triage** (screen many sequences from a FASTA file, ranked by
combined confidence, no structure needed):

```bash
python triage.py sequences.fasta --out triage.csv --top 20
```

**Model calibration check** (is the EC classifier's confidence trustworthy?):

```bash
python -m ml.evaluation --model ml/models/enzyme_classifier_xgb.pkl
```

Retraining the EC classifier from fresh UniProt data:

```bash
python -m ml.training.fetch_enzyme_dataset --per-class 3000
python -m ml.training.build_feature_dataset
python -m ml.training.cluster_sequences          # leakage-aware split groups
python -m ml.training.train_xgb_enzyme_classifier --keep-old
```

## Architecture

```
core/        sequence stats, motif/catalytic/enzyme/function/ligand rules,
             evidence scoring, reporting, export
structure/   PDB parsing + fetch, contacts, pocket scoring, spatial
             catalytic-site geometry, structural evidence fusion
docking/     receptor/ligand prep, pocket detection, AutoDock Vina/GNINA
             adapters (falls back to a mock adapter if neither is installed)
ligand/      SMILES/SDF/MOL2/PDB parsing and chemical validation (RDKit if
             available, a dependency-free fallback parser otherwise)
ml/          EC classifier training (RandomForest + XGBoost), calibration
             evaluation
pipeline.py  full sequence + structure + docking + evidence-fusion CLI
main.py      sequence (+ optional structure) analysis CLI
triage.py    batch sequence-only screening CLI
screen.py    virtual screening: rank a ligand library against one receptor
benchmarks/  redocking and screening-enrichment benchmarks + committed results
paper/       JOSS-style manuscript draft (author fields still to fill)
```

## Limitations

Read this before citing any number from this tool in a paper.

- **Catalytic-residue detection is two-tiered.** `core/catalytic.py` is
  sequence-composition-only (no 3D structure needed, but prone to false
  positives on proteins that merely contain the right residue *types*
  without a real catalytic arrangement). When a structure is available,
  `structure/catalytic_geometry.py` additionally checks whether specific
  residue *instances* are actually close together in 3D space — meaningfully
  stronger evidence, but still a centroid-distance proxy, not a validated
  geometric/orientation model like GASS.
- **Docking is validated on a small redocking set, not a full benchmark.**
  Re-docking four crystal ligands into their own proteins (3 seeds, Vina
  exhaustiveness 8) puts the top-ranked pose within 2 Å of the crystal pose
  in 9 of 12 runs (best-of-9 poses: 11 of 12); `benchmarks/results/redocking.md`
  has the per-complex table. The miss is consistent, not noise: acetazolamide
  in carbonic anhydrase (3HS4) docks 3.3 Å off in all three seeds because
  Vina's scoring has no real treatment of the Zn-coordinating sulfonamide.
  **Site finding is the weak link.** The pocket detector builds pockets from
  the structure's HETATM records, so on a holo structure it just reports the
  ligand site (known-site docking). With all HETATM removed, so that cavity
  detection has to find the site from protein atoms alone, the chosen
  pocket was 6-11 Å from the true site in all four complexes; 1 of 4
  top-ranked poses (3HS4, 1.3 Å) was within 2 Å, only because the padded
  docking box around the wrong pocket (6.3 Å away) still enclosed 12 of the
  crystal ligand's 13 heavy atoms. Use the toolkit with a known site (a
  holo structure, or a box you supply), not as a blind pocket finder.
  Four complexes is a smoke test; a publishable claim needs a standard set
  (CASF-2016, Astex Diverse) and a second engine.
- **Receptor preparation.** The selected chain is protonated at pH 7.4 with
  `pdb2pqr`/PROPKA (pKa-based states, missing side-chain atoms rebuilt,
  H-bond network optimised) and typed and charged by `meeko` (AutoDock4
  types including HD donors, aromatic carbons; template Gasteiger charges).
  If `pdb2pqr`, `propka` or `meeko` is missing, or a residue cannot be
  templated, it falls back with a `RuntimeWarning` to the old writer: no
  hydrogens, so Vina sees no receptor H-bond donors, and charges of 0.0.
  The route used is recorded in each benchmark's results. Caveats: one
  chain only (no multimers); metals are appended with their formal charge
  but pdb2pqr cannot see them, so a metal-coordinating residue could be
  protonated (a warning fires if a polar H lands within 2.5 Å of a metal;
  none did on 1CA2/3HS4/3PTB); cofactors get no hydrogens and zero charge;
  residues without a backbone (e.g. a C-terminal residue resolved only to N)
  are left out of the docking receptor and listed in the prep record.
  Vina's scoring function ignores partial charges, so charges matter only
  for AutoDock4-style scoring; for Vina the preparation changes atom typing.
  On the benchmarks it did not change the conclusions (see Validation).
  `propka` 3.5.1 does not run unpatched on Python 3.14 (it reads
  `self.__annotations__`, which PEP 649 removed); `docking.preparation`
  applies a three-line workaround. Bound ligands, additives and alternate
  conformers are excluded from the receptor. Ligands get real torsion trees
  and Gasteiger charges via `meeko` (a rigid placeholder if meeko/RDKit are
  missing). Docking boxes grow to fit the ligand (`pipeline._box_for_docking`).
  Vina scores are real engine output but not calibrated binding affinities:
  trust relative ranking over absolute magnitude.
- **Pose labels (STRONG/MODERATE/WEAK) are heuristics.** A pose is STRONG
  when at least three of four independent lines of evidence hold (score
  <= -6 kcal/mol; a metal contact or >= 2 hydrogen-bonding residues; >= 3
  nonpolar contact residues; overlap with a known active site) and it has no
  more than 5 steric clashes (more than 5 is always WEAK); two lines is
  MODERATE. They were designed to be inspectable, not fitted to data, and
  they do not detect a wrong pose: in pipeline-mode redocking the 5.4 Å-off
  acetazolamide pose was STRONG while the 0.40 Å-off benzamidine pose was
  WEAK. They also do not track potency: among the screening benchmark's top
  poses, STRONG went to 21/49 actives vs 33/49 weak binders on CA II and
  34/50 vs 29/50 on ER-α. Read them as a
  plausibility check on a single pose, not as a binder/non-binder call.
- **The EC classifier's accuracy depends entirely on how the data is
  split.** With a plain random split the XGBoost model scored 85.0% test
  accuracy, but 86.6% of those test sequences had a near-duplicate in the
  training set (5-mer-containment clusters, see `ml/training/cluster_sequences.py`):
  accuracy was 90.4% on test sequences with a training neighbour and 50.3% on
  those without. Training now holds out whole clusters. On that split the
  model reaches **66.0% test accuracy** (5-fold grouped CV 62.8% +/- 2.0%,
  six EC classes, 15,725 held-out sequences), Brier 0.456, expected
  calibration error 0.045 with mild overconfidence in every mid-range bin.
  Quote the 66%, not the 85%. The clustering is a k-mer proxy for
  CD-HIT/MMseqs2 and will not catch homologs at 30-40% identity, so even 66%
  is probably still optimistic for truly novel folds. This is a self-run
  holdout result, not a benchmark against CLEAN (Yu et al. 2023, *Science*
  379(6639):1358-1363, [doi.org/10.1126/science.adf2465](https://doi.org/10.1126/science.adf2465))
  or any other published method. The legacy 30-feature RandomForest
  (`ml/models/enzyme_classifier.pkl`) is trained on an older dataset the
  cluster file does not cover, so it still uses a random split and its
  accuracy figure is leaky and not comparable.
- **The GNN scaffold (`structure/gnn.py`) is explicitly unimplemented** —
  it builds a real residue-contact graph but the model itself always
  reports unavailable.
- **The rule-based confidence scores are hand-tuned weights, not calibrated
  probabilities.** Only the ML classifier's `predict_proba` output has been
  checked for calibration (see `ml/evaluation.py`); the motif/catalytic/
  enzyme/function/ligand confidence fields elsewhere in the pipeline are
  heuristic, not statistical.
- **GNINA has no supported path on Windows** (no official Windows binary);
  the adapter exists but falls back to the mock engine there.
